# Build391 — actual supported maximum reference, cheap-first execution

## Run card

- Goal: remove the ordinary Auto reference ceiling at the literal effort name `max`; the quality target remains the declared strongest reference, while ordinary execution can still use cheaper models and efforts.
- Source of truth: current signed execution profiles, native model/effort inventory, quota observations and the single persisted OpenClaw task runtime.
- Target: native catalog reference admission and JavaScript reference selection, with deterministic source-derived regressions.
- Allowed: those two bounded mechanisms, their fixtures, resource hash/version metadata and this record.
- Forbidden: always-ultra routing, invented profiles/efforts/accounts, API/billing fallback, a second coordinator, general final-judge calls, replaying frozen quality experiments, editing conversations/queues, reinstalling OhMyBug.
- Symptom: native Auto omitted `ultra`/`ultracode`; the runtime also capped its reference at `max`. An ordinary deep/escalation path therefore could not reach the `ultra` setting used by the actual comparison reference.
- Expected: keep cheap trivial/standard tier entries unchanged; allow a required deep/reference/escalation path to bind the actual supported maximum. Explicit owner effort remains exact.
- Validation: reproduce the old ceiling, native/JS positive and negative controls, unavailable-reference retention, cross-language contract checks, full release gates, verified installation, then fresh metadata-only catalog and installed-module checks.
- Stop condition: unknown or unsupported configuration is unavailable, not a guessed lower 'maximum'; no provider generation is needed merely to prove a configuration-selection branch.
- Output receipt: private timestamped completion/build/install records and exact pushed-source R2 manifest. Source or a staged build alone is not installation.

## Invariants

1. Native support and signed authorization are separate required conditions. A model-name string does not grant an effort.
2. If the known native frontier ceiling lacks an authorized/available profile, record `reference_unavailable`; retain cheaper concrete tiers where valid, but do not use a lower remaining frontier row as a fake reference.
3. `reference_unavailable` must affect runtime reference/deep/escalation selection, not merely appear as an ignored catalog label.
4. An explicit owner `max`, `low` or other supported effort stays that exact constraint. It is not rewritten to a stronger effort.
5. Existing candidate identity tuples, task/policy source binding, quota admission, writer isolation, verifier failure containment, cancellation and prior terminal records remain intact.
6. Historical `max` measurements are not `ultra` evidence. Ledger/cost comparisons remain bound to the exact model/effort pair.
7. The routing mechanism remains dynamic and state/quota-sensitive, with an initial tier policy and measured ledger adjustments. This patch is not proof of fully learned global resource optimality or absence of heuristics.

The optional strict `native_reference_efforts` catalog map carries a native
ceiling for each represented provider/model, not an executable candidate.
Missing unsigned ceilings are therefore detectable for named families and
mixed fan-out as well as ordinary Auto. Legacy catalogs without this metadata
remain readable; their prior terminal selections are not rewritten.
Legacy cheaper-route parity summaries must bind the exact reference model and
effort. Missing reference effort is unknown. A reference-model value may be
derived only from the existing same-model ladder contract, not from arbitrary
unbound records.
