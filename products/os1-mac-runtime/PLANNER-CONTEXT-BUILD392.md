# Build392 — planner-only context projection, Codex execution evidence

## Locked objective and scope

OS1 must route through its single persisted OpenClaw task, select supported model and reasoning settings, and return actual native Codex results. The quality reference does not force every task onto the frontier model. No ChatGPT relay, API inference, additional account, OhMyBug, duplicate coordinator or final mandatory model judge is introduced.

This repair changes only what the **tool-free planning model sees** of a typed session-handoff envelope. The full original task, source fingerprint, policy, memory authorization allowlist and native worker context remain authoritative and unchanged.

## Observed evidence

Installed391 actually completed two newly frozen synthetic task pairs:

- Structured record extraction: Auto selected and native metadata confirmed `gpt-6-luna/low`; all8 source/JSON groups passed, as did the predeclared `gpt-6-astra/ultra` direct reference.
- File implementation: Auto selected and native metadata confirmed `gpt-6.1-sol/medium`; the source contract and18 functional groups passed, as did the same direct reference.

All four final answer/artifact records were locked before scoring. The implementation artifact initially received a **harness false negative**: a driver required0600 while the native worker correctly produced a regular0644 file inside a0700 isolated workspace. The reference arm had no0600 gate. The original failure/score remain immutable; byte-identical locked code passed the unchanged sandboxed checker and an independent repeated check. No model was rerun to repair this observer mistake.

A subsequent real OS1 UI request returned a fixed nonce from native Codex using `gpt-6-luna/low`, and the UI task tree showed one worker plus the coordinator. This establishes the actual UI/native return path, not general task-quality parity. That run took100.29seconds within the Core, including78.161seconds of planning. An actual local-model request log attributes most of that interval to prompt prefill, then JSON generation; cold loading alone does not explain it.

The planner input included187 authorized session UUIDs, although the planner has no retrieval tools. Auto already uses a small availability summary rather than the full46-row execution catalog; this is not a missing catalog-compaction repair.

## Repair and invariants

For a strictly recognized `os1-session-handoff-v3` context with valid conversation/snapshot bindings, replace **only the planner copy** of `memoryPaging.allowedSessionIDs` with an explicit host-only authorization descriptor containing the exact ordered-list SHA-256 and count. It grants no retrieval authority. Keep all other context values and the entire RCC policy in the planning prompt.

- Preserve the full original allowlist and task in the host. Never recompute a source fingerprint from the projected planner view.
- Keep original request/objective, material references, route/schema, native tuple authorization, quota admission, writer leases, cancellation and adoption checks.
- Do not sort, deduplicate or case-fold the list before hashing.
- Malformed, unknown, mismatched, future-format and already projected contexts stay unchanged.
- Do not enlarge small prompts with a longer descriptor.
- Use the projection only in graded Auto/graded explicit planning. Preserve legacy exact-candidate planning behavior.
- No statement that a prompt-size reduction itself proves a latency, quota or quality improvement.

## Validation and claim boundary

Focused negative and positive source-derived fixtures, unchanged-context/binding checks, full JavaScript/native/release gates, verified local installation and a fresh installed UI roundtrip are required before adoption. Tests and staging are not installation. Private receipts preserve source/build identity and the original user sessions/queue.

The two391 comparisons are bounded synthetic diagnostics, not representative all-task noninferiority, universal latest-model parity or measured subscription-quota savings. Their outputs are not automatically imported as routing certificates. Native execution verification and task-quality verification remain distinct.

Relevant repair-method sources inspected: [ReAct](https://arxiv.org/abs/2210.03629), [intrinsic self-correction limitations](https://arxiv.org/abs/2310.01798). Actual artifacts and executed checks, not those papers or generated agreement, decide adoption.

The captured UI input retains20,886 instruction bytes (including18,554 policy bytes) and1,024 schema bytes. Only the message shrinks9,302→1,809 bytes; total visible prompt31,212→23,719 bytes. This is a deterministic byte measurement, not a claimed token/latency percentage. A mixed-case Swift UUID binding discovered by independent review is covered: normalize only validated conversation-ID identity for comparison, never the authoritative allowlist or its ordered hash. The new focused fixture is wired into the release gate.
