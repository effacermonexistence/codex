# Conditional calibrated route admission inside the existing Core

This is a conditional execution path, not a calibrated production result. No
production capability, data, learned weights, threshold or live registration is
shipped. The optional `calibratedRoutePredictor` constructor value defaults to
null. A plain callback/task flag is rejected; the projector factory's branded
callable and branded inference are required. Existing SHADOW stays advisory.

A fresh ordinary Auto task must retain its current intent-v2 host binding,
positive canonical first-turn envelope, no native/history/source material,
byte-original objective/instruction, one read-only node/final owner, no added
paths/dependencies and a current independently full R0 contract. Owner provider,
model, effort, ceiling and quality pins do not borrow this path. No generic DAG,
writer, resumed session, legacy reinterpretation or statistical R0 source exists.
The task-contract source hash must explicitly be null: missing/unknown and
non-null source identities are not converted to source-free. Existing task wire
validation still rejects new source fields rather than expanding the schema.

Core first resolves its unchanged R0 plan. A qualified current-host evidence
result may change only the candidate ID, only to an already R0-eligible native
entry in the same transport/account/tool/permission cohort. The frontier quality
reference is independently resolved and runnable; it is not silently identified
with an already-cheap current R0 tuple. Source/task/plan/catalog/config/reference
bindings and a strictly lower independently witnessed resource total than R0
are checked. Unknown components/cost, equal cost, missing/expired/revoked/OOD
qualification or any optional error preserves R0. A P7 parent-token mean is not
split into the selector's ten remaining-node components.
The loader must validate complete TRAIN whole-route episodes (primary plus
optional checker-failure reference fallback and disjoint host overheads), not
single-attempt cost with an invented zero retry reserve. Two attempt and native
dispatch slots must remain available; existing committed intents are not refunded.

The actual host builds a normal contract-certified tier route and its fixed
reference ladder, never `adapter_bound`. Existing full operational answer checks,
reference escalation, permission/native ticket/ACK, reservation, budgets and final
adoption remain authoritative. A forecast is not output verification or parity.

Qualification is read again after the mandatory fresh catalog and immediately
before the ticket/transactional dispatch intent. Loss before any attempt restores
the current original R0 plan; no native attempt has begun. Re-resolution clears
old statistical provenance. A lost/unknown dispatched effect is never replayed;
ordinary Core cancellation/unknown-state custody applies. A failed, terminated,
no-effect cheaper answer can escalate once through the existing reference ladder;
its failed raw attempt/resources remain recorded. No already-running attempt is
silently replaced by a new forecast.
The initial catalog admission metadata and full-contract semantic fields are
frozen independently of statistical semantic-family identifiers; these are not
assumed to equal the native request class. Only renewable contract expiry is
excluded from that semantic-identity hash. If current R0 itself is unavailable,
the saved original plan/rows are restored for trace custody and the actual
readiness error holds with zero attempts; saved rows do not authorize dispatch.

Synthetic evidence remains `qualified_synthetic_fixture`, never production
qualified. Its Core opt-in is a host-only constructor `calibratedRouteFixtureExecutor`
(default null), bound by function identity to the injected fake executor and a
canonical private OS temporary state directory. The normal plugin does not set
this test authority; task/model JSON cannot. This host testing boundary is not a
claim that arbitrary same-process developer code is sandboxed or trustworthy.

Private admission trace records baseline/adopted plan and receipt identities;
it is not a serialized capability and cannot re-grant authority after restart.
The strict public result/Swift projection shape is unchanged. Deployment must
separately close the explicit resource inventory over the new projector/loader
modules; no source-only test establishes installation or actual efficacy.
