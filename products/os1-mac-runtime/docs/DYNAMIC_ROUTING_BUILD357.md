# Build 357: exact local response and actual transport admission

## Scope
The existing signed v66 router already ranks an admitted set using actual model inventory, quality admission, measured usage, recent outcomes and fresh quota. It still uses bounded keyword/grammar classifiers. Dynamic routing is not a claim of heuristic-free inference.

This change enforces existing RCC distinctions at the client execution boundary; it does not replace the private model-ranking policy or invent quality-equivalence evidence.

## Executed path
- Auto response-liveness questions such as `야 체크해 봅시다. 너 되냐?` use the exact local ResponseAvailability executor before model/quota discovery. The private, read-back-verified receipt states local execution, no model invocation and no subscription usage. Broad completion/installation, external health, tools, attachments and explicitly named provider tests do not qualify.
- Every native attempt enters DynamicRouteAdmission with its actual transport and allowance identity. Tool-free GPT over Codex remains `codex_app_server / openai_codex`; Claude's CLI remains a shared Anthropic pool. Fresh exhausted quota is rejected before native invocation; stale or missing observations stay unknown. Signed-policy eligibility is explicitly not output-quality verification.
- The common admission kernel rejects unauthorized capability/scope, mismatched transport/pool, invalid quality/configuration provenance, unavailable service transport and explicit forbidden pools. Its multi-candidate selector only compares admitted candidates under a common criterion and comparable observed usage estimates. The existing signed router remains the producer of native model/effort selection.
- A real single run is shown as one observed-execution card, separate from ParallelAgentTask plans. Its detail window uses actual runtime/result fields, never invented child workers or progress. Optional historical observation metadata cannot poison session loading. Passive updates do not activate backend windows.

## Source / runtime boundaries
- Generic consumer ChatGPT automatic send/readback is **not implemented** here. The current ChatGPT choice is a handoff, not an adopted execution. The GPT chat-shaped native lane is not consumer ChatGPT.
- Claude consumer chat and Claude Code share subscription limits. A renamed or tool-free lane is not a second free pool.
- Exact-domain local response verification is not general latest-maximum model parity. Substantive tasks retain their existing task/reference checker and fallback boundaries.
- Handy, credentials, global billing, repository visibility and unrelated products are outside scope.

## Verification
Deterministic local/transport regressions cover actual receipt readback, raw request/output binding, exhausted/forbidden pool, chat transport mismatch, unknown evidence, scope exclusions and no native calls. App fixtures cover one-card/detail-window binding, focus, run replacement, parallel precedence and lenient optional telemetry decoding. Actual installation, live GUI receipt and recovery-object identity are recorded separately; source tests alone are not an installation receipt.
